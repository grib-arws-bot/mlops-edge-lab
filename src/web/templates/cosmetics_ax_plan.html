화장품 AX 기획

그립이 진행 중인 화장품 제조 AX 실증 2건(강원·충북)을 같은 개발팀이 동시에 진행할 때의 시스템 구성 예시 — 개념 정리용, 실제 개발 착수 전 기획 단계입니다.

1. 두 과제 개요
둘 다 배치형 화장품 제조공정에 AI를 적용하는 과제지만, 기술 난이도와 규모가 다릅니다.
① 강원정보문화산업진흥원 과제
대상 공정천연물 추출 · 미생물 발효 · 초고압 나노분산 (3대 핵심공정)
기간2026.09 ~ 2027.12 (2개년, 16개월)
총사업비3억 6,350만원
AI 기술XGBoost·GRU/LSTM·물리모델+RF·IsolationForest + sLLM AI Agent + MLOps(드리프트 감지·Model Registry)
KPI생산량 15%↑, 불량 8%→2%(75%↓)
② 세화피앤씨 과제(충북테크노파크 운영)
대상 공정유상용해·수상용해·혼합 등 배치 공정
기간협약일 ~ 2027.08.30 (12개월)
총사업비9,080만원
AI 기술XGBoost(품질예측·불량판정)·SHAP(원인분석)·IsolationForest→LSTM-AE(설비이상감지) — 정형 ML 전용, LLM 없음
KPI불량판정 Recall≥90%, 품질예측 MAPE≤5%, TTA 공인검증
2. 공통점 · 차이점
공통점
  • 배치형 화장품 제조공정의 실측 시계열 데이터(온도·RPM·압력·전류 등)를 다룸
  • Lot/Batch ID를 단일 식별자로 삼는 데이터 거버넌스가 최우선 과제
  • PLC/IoT Gateway 기반 센서 수집(RS-485·4-20mA) — 물리 계층 패턴이 사실상 동일
  • 4계층 아키텍처(수집→저장·처리→AI분석→서비스)로 설계
  • Human-in-the-loop — AI 추천값은 사람 승인 후에만 현장 반영
차이점
  • 강원 쪽이 기술 난이도·규모 모두 훨씬 큼(딥러닝·sLLM Agent·MLOps 드리프트 감지 포함)
  • 인프라 요구: 강원=GPU 서버 필요, 세화=CPU 정형모델로 충분
  • 검증 방식: 강원=3자 협의 검증, 세화=TTA(외부 공인기관) 인증 필요
3. 핵심 발견 — 실제로 "하나의 팀"이 맞음
두 과제의 실제 투입 인력 구성을 비교해보니, 핵심 인력 상당수가 두 과제에 걸쳐 중복 투입되도록 계획돼 있습니다 — 같은 사람이 과제마다 다른 역할(예: 한쪽은 총괄 PM, 다른 쪽은 실무 개발자)로 참여합니다. 일정도 "비슷한 시기에 겹치는" 정도가 아니라, 세화 과제 기간(12개월) 전체가 강원 과제 기간(16개월) 안에 통째로 포함되는 관계입니다.
→ 그래서 이 두 과제는 순차적으로 다룰 수 없고, 처음부터 "동시 진행"을 전제로 시스템과 인력 운영을 설계해야 합니다.
4. 시스템 구성 예시
이 프로젝트(MLOps-Edge-Lab)가 이미 지키는 원칙과 같습니다 — "팀·설계 패턴은 공유하되, 데이터·배포 환경은 완전히 분리한다." 두 수요기업 모두 보안서약서·자료 반출입 절차를 요구하므로, 이건 선택이 아니라 계약상 의무이기도 합니다.
그립 공통 자산 — 공통 인력 풀 · 재사용 가능한 설계 패턴(코드 골격일 뿐, 실행 인스턴스 아님) · 사내 개발/스테이징 서버(고객 데이터 없이 코드만 개발)
↓ 패턴만 적용, 데이터는 안 섞임 ↓
배포 A — 강원 과제 (완전 격리)
센서·PLC·IoT Gateway (추출기·발효기·고압균질기)
Lot/Batch RDB (전용)
MLOps 코어 — Model Registry·드리프트 감지·Rollback
AI 모델 4종 + AI Agent(sLLM, GPU)
대시보드·모바일 UI (승인 워크플로)
배포 B — 세화 과제 (완전 격리)
센서·RS-485 제어판넬·IoT Gateway (유상·수상·혼합 믹서)
Batch InfluxDB + PostgreSQL (전용)
AI 모델 4종 (XGBoost·SHAP·IsolationForest→LSTM-AE, CPU)
대시보드 UI (TTA 검증 대응 리포트)
✕ 네트워크·DB·모델 저장소 물리적으로 완전 분리 — 두 배포 사이에 연결 경로 자체를 만들지 않음
5. 파이프라인 구조 — 모델별 파인튜닝·RAG 매핑
강원은 4축 예측모델 + sLLM Agent로 총 5개, 충북은 정형 ML 4개(그중 SHAP은 별도 학습 없는 사후설명 기법)입니다. 파인튜닝·RAG·Agent(도구호출)는 강원의 sLLM 한 곳에만 해당됩니다.

6. 다음에 확인할 것
  • 두 과제 모두 "총괄 PM" 역할과 책임 소재를 착수 전에 명확히 확정
  • 두 배포 환경을 물리적으로 어디에 둘지(그립 자체 서버 vs 고객사 현장 On-premise vs 클라우드) 미확정 — 착수 후 확인 필요
  • 강원 과제의 MLOps 방법론(드리프트 재보정 등)을 세화 과제에도 적용할지는 미정 — 세화는 정형 ML이라 필수는 아니지만 같은 팀이라 학습 비용 대비 적용 여지는 있음
  • 중복 투입되는 핵심 인력의 시기별 부하가 몰리지 않는지는 별도 내부 자료(실명 포함)로 관리 — 이 페이지에는 개념만 남김
