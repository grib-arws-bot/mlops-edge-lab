# MLOps-Edge-Lab 회고 및 인수인계

> **이 문서의 목적**: 이 프로젝트(개인 학습용)를 마무리하면서, 뒤이어 시작할 **강원·충북 화장품 제조 AX 상용 프로젝트**(별도 repo/폴더/세션)가 검토하고 재사용할 수 있도록 방향성·정책·기술·함정을 정리한다. 원본 상세 근거는 `docs/의사결정_로그.md`(131개 항목, 2026-09-17~09-28)에 전부 있음 — 이 문서는 그중 **다음 프로젝트에 실제로 옮겨갈 만한 것**만 추린 요약이다.
>
> **가장 중요한 한 줄**: 이 프로젝트는 "학습용이라 보안·거버넌스를 느슨하게 가도 된다"는 전제로 여러 결정을 내렸다(예: 의사결정_로그 68번). **상용 프로젝트는 이 전제가 통째로 틀렸다** — 아래 "6. 상용 전환 시 반드시 보완할 것"을 가장 먼저 읽을 것.

## 1. 프로젝트 개요 및 완료 현황

목표: ① MLOps 파이프라인 구축(데이터→파인튜닝→양자화→RAG→Agent→엣지 배포), ② 엣지 디바이스용 sLLM 구축. 둘 다 로드맵 1~7단계로 완료됨.

| 단계 | 내용 | 상태 | 핵심 산출물 |
|---|---|---|---|
| 1 | 개발환경(uv, MLflow) | ✅ | `~/mlops-edge-lab/.venv`, MLflow(SQLite backend) |
| 2 | 데이터 추출(멀티포맷) | ✅ | `src/extract/`, 738건 코퍼스 (품질 = 완료가 아니라 "재검토 후보 축소"까지만, 아래 참고) |
| 3 | 파인튜닝(LoRA) | ✅(toy 데이터) | `src/train/`, Qwen3-4B-Instruct + LoRA, ROUGE-L(문자 단위) |
| 4 | 양자화(GGUF) | ✅ | Q4_K_M, 7.5GB→2.3GB, CPU/GPU 듀얼 백엔드 실측 |
| 5 | RAG(FAISS) | ✅ | 실제 코퍼스 738건, 하이브리드 검색(BM25+임베딩) |
| 6 | Agent(rule+LLM) | ✅ | 판정=규칙, 검색=LLM 도구호출, 장비제어 승인 게이트 |
| 7 | 엣지 에뮬레이션 | ✅(하한선 추정) | cgroup 기반, **실제 엣지 하드웨어 검증은 상용화 시점으로 유보(의사결정_로그 73번)** |

부가 확장: 스마트교육 트랙(RAG+파인튜닝 비교), 화장품 제조 AX 개념검증(`/cosmetics-poc`), BidRadar 외부 연동 API, MSDS+AI Hub 물성치 조회, Evidently 드리프트 감지, MLOps 표준 4요소(레지스트리·모니터링·데이터버저닝·CI/CD) 전부 완료.

**중요한 미해결/불완전 항목** (얼버무리지 않고 명시):
- 센서 임계값 다수가 placeholder였고, 일부(질소·헬륨·아르곤)는 "농도 상한"이 아니라 "산소결핍(O2<18%)"으로 측정 대상 자체가 잘못 설계돼 있었음(의사결정_로그 65·66번) — **강원·충북의 실제 설비 안전기준은 반드시 현장 전문가가 처음부터 정의**해야 하며, 이 프로젝트의 placeholder 패턴을 그대로 베끼면 안 됨.
- 데이터 추출 "성공"은 "비어있지 않음"만 의미(13번) — 사람이 원문 대조한 골든셋은 없음. 상용은 최소 샘플 검수 절차 필요.
- ROUGE 자동평가가 한국어 조사·어미 차이를 사실상 무시하던 결함이 있었고(75번), 재학습 게이트가 한동안 이 결함 위에서 동작했음(77번에서 수정) — **"자동 지표 통과"를 곧이곧대로 믿지 말고, 그 지표가 실제로 뭘 재는지 항상 실측으로 재검증**하는 습관이 필요.
- 엣지 실물 하드웨어 검증 없음 — cgroup 에뮬레이션은 CPU 코어/메모리 상한만 흉내내고 명령어셋·디스크I/O·발열은 재현 불가(32번). "하한선 추정"이지 정확한 예측이 아님.

## 2. 핵심 기술 스택

| 영역 | 채택 | 검토했던 대안·채택 이유 |
|---|---|---|
| 베이스 sLLM | Qwen3-4B-Instruct-2507 (Apache-2.0) | EXAONE(한국어 최상, NC 라이선스라 상용 불가) / Solar(10.7B, 엣지엔 큼) 제외 — `docs/모델_비교.md` |
| 파인튜닝 | LoRA(r=16,α=32) + transformers/peft/trl | QLoRA는 더 큰 모델용으로 유보(3B/4B는 20GB VRAM에 여유) |
| 양자화 | llama.cpp GGUF Q4_K_M | 7.5GB→2.3GB, CPU 19~203 t/s · GPU 87~3793 t/s(pp/tg) 실측 — 하나의 파일로 GPU 유무 모두 대응 |
| RAG 임베딩 | intfloat/multilingual-e5-small | 엣지 실시간 제약 우선, bge-m3는 필요시 교체 가능하게 설계 |
| RAG 검색 | FAISS(IndexFlatIP) + BM25 하이브리드 | 별도 벡터DB 서버 없이 프로세스 내 사용(엣지 철학과 일치) |
| Agent 설계 | 판정=규칙(`rules.py`), 검색=LLM 도구호출 | LLM이 위험도 판정·장비제어를 직접 하지 않게 구조적으로 분리 |
| 문서 추출 | PyMuPDF + pyhwp + LibreOffice 폴백 + Tesseract-kor | 포맷별 폴백 사슬, "조용한 빈 결과 금지" |
| MLOps 4요소 | MLflow(레지스트리) / Prometheus+Grafana(모니터링) / DVC(버저닝) / GitHub Actions 자체 러너(CI/CD) | |
| 드리프트 감지 | Evidently AI(PSI, 자체 재보정 임계치) | 업계 관례 임계치(0.1/0.25)가 이 프로젝트 지표엔 안 맞아 실측으로 재보정(2.0/8.0) — **임계치는 반드시 실측, 관례값을 그대로 쓰지 말 것** |
| 웹서빙 | FastAPI + Jinja2 + nginx(단일 외부 포트 서브패스 라우팅) | 신규 의존성 최소화, 서버 admin이 포트 1개만 허용하는 제약에 맞춤 |

## 3. 재사용할 만한 설계 원칙

이 프로젝트 전반에 반복적으로 나타난, **프로젝트 성격과 무관하게 일반화되는** 원칙들:

1. **실측 우선, 관례값 불신** — 업계 표준 임계치·문서 스펙도 이 프로젝트의 실제 데이터·지표로 재검증 후 채택(드리프트 임계치, 센서 기준치, AI Hub 라벨 건수 등 여러 번 반복 확인됨).
2. **판정 권한 분리(rule vs LLM)** — 되돌리기 어렵거나 안전에 관계된 결정(위험도 판정, 장비 제어, 고위험 조치 승인)은 코드 규칙이 하고, LLM은 검색·요약 같은 저위험 판단만 한다. 모든 결정에 권한 태그(`Decision(authority=...)`)를 남겨 추적 가능하게 함.
3. **근거 없는 답변 금지 + 출처 항상 표시** — RAG 답변은 검색된 근거만 사용, 없으면 "모른다"고 답하게 프롬프트에 명시하고 화면에도 원문 근거를 그대로 노출.
4. **폴백 사슬 + 조용한 실패 금지** — 포맷별 변환 실패, 데이터 미검증 등은 항상 이유를 기록. "성공률 100%"라는 숫자를 볼 때마다 "무엇을 성공으로 정의했는지"를 의심할 것.
5. **LLM 자유텍스트 필드는 관대한 파서 필수** — `json.loads` 직접 호출은 언젠가 반드시 깨짐(정규식 기반 폴백 파서를 처음부터).
6. **미해결 사항은 기록하고 넘어가되, 절대 숨기지 않는다** — 화면에 "설계됨/미자동화" 같은 배지로 실제 구현 상태를 정직하게 노출(의사결정_로그 35·41번). 나중에 다시 볼 때 "이미 다 됐다고 착각"하는 사고를 막음.
7. **의사결정 로그 습관** — 결정할 때마다 왜/무엇을 검토했는지 즉시 기록. 이번 인수인계 문서 자체가 이 습관 덕에 가능했음.

## 4. 인프라/운영에서 반복된 함정 (그대로 재현하지 말 것)

- **git 배포와 수동 배포(scp/ssh) 혼용 금지** — 같은 경로에 미추적 파일이 서버에 남으면 이후 `git pull` 기반 CI/CD가 조용히 실패한다(76·97번, 실제로 하루 가까이 못 알아챈 사고). 서버에 직접 뭔가 테스트할 땐 배포 스크립트가 그 경로를 덮어쓸 수 있다는 걸 항상 의식.
- **systemd 재시작 간격을 너무 짧게 잡지 말 것** — 외부 서비스(GitHub Runner 등)가 이전 세션을 정리하는 데 걸리는 실제 시간을 실측하고 `RestartSec`을 그보다 넉넉하게(69번, ~90초 vs 5초 설정으로 재시작 루프에 빠짐).
- **배포 헬스체크는 고정 sleep이 아니라 폴링** — 기능이 늘수록 기동 시간도 늘어난다(52번).
- **사내망 프록시가 요청을 변형할 수 있음** — 상대경로 fetch가 절대경로+퍼센트인코딩으로 도착하는 현상 확인(42·57번), 원인은 네트워크 계층이라 완전 차단 불가 → 프론트에 재시도+방어적 검증 필요. **근본 해결은 HTTPS**(이번엔 범위 밖으로 보류했으나 상용은 필수로 고려).
- **한 서버 뒤에 여러 앱을 nginx로 묶을 때 절대경로 하드코딩에 주의** — 서브패스 이동이 안 되는 앱(고칠 수 없는 벤더 앱)은 루트에 두고, 소스를 가진 앱을 서브패스로 내리는 게 정답(128번). 정적 자산 마운트 경로 충돌(`/static`)도 실제로 발생했음.
- **NVML/nvidia-smi 버전 불일치**는 관찰됨(2026-09-30) — 커널 모듈과 라이브러리 버전이 어긋나면 모니터링만 깨지고 실제 CUDA 추론은 살아있을 수 있음(구별해서 확인하는 법: 실행 중 프로세스의 `/proc/<pid>/fd`에서 `/dev/nvidia*` 핸들 보유 여부). 상용 전 반드시 깨끗하게 정리.
